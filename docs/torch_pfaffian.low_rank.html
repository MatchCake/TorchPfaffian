torch_pfaffian.low_rank.compiled_low_rank_pfaffian module¶

class torch_pfaffian.low_rank.compiled_low_rank_pfaffian.CompiledLowRankPfaffian¶

Bases: LowRankPfaffian

LowRankPfaffian whose tensor computations run through torch.compile.

Every method has the signature, results and gradients of LowRankPfaffian; the inputs are validated in eager Python as there, and only the tensor computation behind it (one core per method) is compiled, which fuses its small operators into a few kernels. That removes most of the per-operator overhead that dominates small inputs: on CPU, the inverse updates of a single n = 32 matrix take about half the eager time, and on CUDA the per-call launches drop by about 2x. The ratios alone gain little on CPU, where the fixed cost of a compiled call (about 20 µs) is close to that of the eager operators.

Each core is compiled on its first call (a few seconds) with dynamic=None: a second shape makes the sizes dynamic, so a matrix that grows step by step (PfaffianChain) is compiled twice, not once per size. Compilation needs what torch.compile needs on the platform (a C++ compiler on CPU, Triton on CUDA). A core whose compiled call fails while its eager computation succeeds (no compiler, or a torch.compile bug of the installed PyTorch) runs eagerly from then on, with a RuntimeWarning the first time; an error that the eager computation raises too is raised as is. The compiled cores are shared by all callers in the process and are reset by torch._dynamo.reset(). Use it for long runs (Monte Carlo chains, many samples), where the compilation is amortized; LowRankPfaffian stays the default.

torch_pfaffian.low_rank.low_rank_pfaffian module¶

class torch_pfaffian.low_rank.low_rank_pfaffian.LowRankPfaffian¶

Bases: object

Ratios of Pfaffians and inverse updates under skew-symmetric low-rank updates.

For a skew-symmetric invertible A and u of shape (n, 2k), the updated matrix is

\[\begin{split}A' = A - u J u^T, \qquad J = \begin{pmatrix} 0 & I_k \\ -I_k & 0 \end{pmatrix}\end{split}\]

(the convention of lrux, arXiv:2602.05255), and with the 2k x 2k skew-symmetric matrix R = J + u^T A^{-1} u,

\[\frac{\mathrm{Pf}(A')}{\mathrm{Pf}(A)} = \frac{\mathrm{Pf}(R)}{\mathrm{Pf}(J)}, \qquad A'^{-1} = A^{-1} + (A^{-1} u) R^{-1} (A^{-1} u)^T.\]

The ratio costs O(n^2 k) instead of the O(n^3) of a new Pfaffian, and so does the updated inverse (Woodbury identity), which is skew-symmetric up to round-off. A rank-2 update u = (x, y) adds y x^T - x y^T to A; replacing one row and column (ratio_replace()) costs O(n) for the ratio.

Only tensor operations are used, so every method is batched, runs on any device without host synchronization, and is differentiable. Complex inputs use the transpose, not the conjugate transpose, as the Pfaffian is bilinear. float16, bfloat16 and complex32 inputs are computed in float32 or complex64 with a UserWarning, as in pfaffian(). When a ratio is zero, the updated matrix and R are singular: the returned inverse is then meaningless (huge or non-finite) and should be recomputed from the updated matrix when it is needed.

Gradients are exact for any skew-symmetric construction of the inputs (e.g. from circuit parameters). The gradient with respect to a raw inverse leaf is projected onto skew-symmetric matrices (SkewGradient), the convention of pfaffian(). The gradients with respect to update, change, border and corner sit on the entries that are read: when they are slices of a larger skew-symmetric leaf matrix, only the skew-symmetric part of that matrix’s gradient is meaningful.

PfaffianUpdater chains such updates, with delayed inverse updates.

On CPU, without a graph to build (torch.no_grad(), or inputs that do not require grad), ratio, ratio_and_inverse, ratio_replace and ratio_replace_and_inverse run in one call of the compiled Rust extension instead of a handful of PyTorch operators, which dominate small inputs (a rank-2 ratio and inverse of one n = 32 matrix: 17 us instead of 77 us). Updates wider than rank 2 on large batches keep the PyTorch path, whose matrix products are faster there.

classmethod ratio_extend(inverse: Tensor, border: Tensor, corner: Tensor) → Tensor¶

Ratio of Pfaffians when a skew-symmetric matrix grows by 2k rows and columns.

For the bordered matrix

\[\begin{split}M = \begin{pmatrix} A & B \\ -B^T & C \end{pmatrix}, \qquad \frac{\mathrm{Pf}(M)}{\mathrm{Pf}(A)} = \mathrm{Pf}\left(C + B^T A^{-1} B\right),\end{split}\]

the Pfaffian of the 2k x 2k Schur complement, in O(m^2 k) from A^{-1}. This is the step of sequential (qubit-by-qubit) sampling of matchgate circuits, where a qubit adds the 2 x 2 block of its two Majorana modes: the conditional probability of an outcome is |ratio| / 2. A may be empty (m = 0), when the ratio is Pf(C).

Only C depends on the outcome, so several candidate corners are evaluated at the cost of one: give them a leading dimension, e.g. corner of shape (2, ..., 2k, 2k) for the outcomes 0 and 1, and the ratios have shape (2, ...) (A^{-1} B is computed once, at the batch shape of inverse and border). PfaffianChain keeps A^{-1} from one step to the next.

  • corner – Skew-symmetric block C of the new rows and columns, of shape (..., 2k, 2k).

classmethod ratio_replace(inverse: Tensor, index: Tensor | int, change: Tensor) → Tensor¶

Ratio of Pfaffians when one row and the matching column of a skew-symmetric matrix change.

Row i of A becomes A[i] + c and column i becomes A[:, i] - c, so that A' stays skew-symmetric; c_i has no effect (the diagonal stays zero, and it only meets the zero diagonal of A^{-1}, up to round-off). This is the rank-2 update u = (c, e_i) of ratio(), with a one-hot e_i, for which

\[r = \frac{\mathrm{Pf}(A')}{\mathrm{Pf}(A)} = 1 + c^T A^{-1} e_i.\]

It reads one column of the inverse and costs O(n). To replace row i by a new row x (with x_i = 0), pass change = x - A[i]. ratio_replace_and_inverse() also updates the inverse.

torch_pfaffian.low_rank.pfaffian_chain module¶

class torch_pfaffian.low_rank.pfaffian_chain.PfaffianChain(batch_shape: tuple[int, ...] | Size = (), *, dtype: dtype = torch.float64, device: device | str | None = None, compiled: bool = False)¶

Bases: object

Pfaffian of a skew-symmetric matrix that grows block by block, with the ratio of each growth step.

The state is the inverse of the current m x m matrix A and its Pfaffian. A step appends 2k rows and columns, the coupling B (m x 2k) and the block C (2k x 2k):

\[\begin{split}\begin{pmatrix} A & B \\ -B^T & C \end{pmatrix}, \qquad \text{ratio} = \mathrm{Pf}\left(C + B^T A^{-1} B\right),\end{split}\]

in O(m^2 k) (see ratio_extend()), so the Pfaffians of all the leading blocks of an n x n matrix cost O(n^3) in total, against O(n^4) when each is computed anew.

This is the loop of qubit-by-qubit sampling of a matchgate circuit (as in MatchCake). The probability of the outcomes y_0 ... y_j is 2^{-(j+1)} |Pf(M_j)|, with M_j the principal submatrix of Lambda + Lambda_y on the Majorana modes of qubits 0 ... j. Qubit j appends its two modes: B is the covariance between the modes of the qubits sampled so far and its own, and C its 2 x 2 block, which depends on the outcome y_j. ratios() gives the ratio for every candidate block (the conditional probabilities are |ratio| / 2), and extend() appends the sampled one:

chain = PfaffianChain((shots,), dtype=covariance.dtype)
for qubit in range(n_qubits):
    modes = slice(2 * qubit, 2 * qubit + 2)
    border = covariance[..., : 2 * qubit, modes]                   # (shots, 2 qubit, 2)
    corners = covariance[..., modes, modes] + outcome_blocks       # (shots, 2, 2, 2), y = 0 and 1
    probabilities = chain.ratios(border, corners).abs() / 2        # (shots, 2)
    outcome = torch.multinomial(probabilities, 1)[..., 0]          # (shots,)
    chain.extend(border, corners[torch.arange(shots), outcome])

Every operation is a batched tensor operation on any device, without host synchronization, and is differentiable: gradients are exact for any skew-symmetric construction of the matrix (e.g. Lambda(t) from circuit parameters). The chain reads the blocks B and C and never -B^T, so when they are slices of a skew-symmetric leaf matrix, its gradient sits on those blocks and only its skew-symmetric part, g - g^T, matches that of pfaffian(). A zero ratio (an outcome of probability zero) makes the grown matrix singular: such a block must not be appended.

The batch dimensions of the borders and corners broadcast with batch_shape. The dtype is float32, float64, complex64 or complex128.

torch_pfaffian.low_rank.pfaffian_updater module¶

class torch_pfaffian.low_rank.pfaffian_updater.PfaffianUpdater(matrix: Tensor, *, max_delay: int = 8, compiled: bool = False)¶

Bases: object

Successive low-rank updates of a skew-symmetric matrix, with Pfaffian ratios and delayed inverse updates.

The state is the inverse A_0^{-1} of the last merged matrix and, for each of the tau updates accepted since, the projection a_t = A_{t-1}^{-1} u_t and R_t^{-1} (see LowRankPfaffian for the convention A_t = A_{t-1} - u_t J u_t^T). The current inverse is never formed between merges:

\[A_\tau^{-1} u = A_0^{-1} u + \sum_{t=1}^{\tau} a_t R_t^{-1} (a_t^T u) = A_0^{-1} u + P D (P^T u),\]

with the projections side by side, P = (a_1, ..., a_tau), and the block-diagonal D of the R_t^{-1}, so an update costs O(n^2 k + \tau n k^2) and does not rewrite the n x n inverse. After max_delay accepted updates the corrections are merged into the inverse. lrux (arXiv:2602.05255) suggests max_delay of about n / (20 k).

Every operation is a tensor operation on the batch, without host synchronization, so a batch of Monte Carlo walkers is updated at once: accept() takes a mask of the walkers whose move is accepted, and leaves the others unchanged. Gradients flow through the state like through any tensor computation.

With compiled=True, each step runs through torch.compile (see CompiledLowRankPfaffian): a few seconds of compilation on the first steps, then less per-call overhead on small matrices.

On CPU without a graph to build, accepted moves are applied to the inverse at once, in place, by the Rust kernels of LowRankPfaffian instead of being delayed, which is faster; delay then stays 0. The results are the same up to round-off. The updater copies an inverse it did not compute (from_inverse()) or that it returned (inverse) before updating it, so tensors held by the caller are never changed.

Round-off accumulates over many updates, mostly in single precision. reset() recomputes the inverse from the current matrix (which the caller keeps); the running pfaffian is the Pfaffian of the initial matrix times the accepted ratios, and can over- or underflow over long runs.

The input matrix is a skew-symmetric matrix of shape (..., n, n), in float32, float64, complex64 or complex128.

Identity whose backward pass projects the gradient onto skew-symmetric matrices, (g - g^T) / 2.

A function of a skew-symmetric matrix only depends on it through its skew-symmetric directions, but how an implementation reads the matrix (an upper triangle, a transposed product) decides where autograd puts the gradient of a raw leaf matrix. pfaffian() returns the skew-split convention Pf(A) A^{-T} / 2; wrapping the skew-symmetric inputs of the low-rank updates in this identity gives them the same convention. The gradient of any parameter the matrix is built from (keeping it skew-symmetric) is unchanged, since only the skew-symmetric part of the gradient enters it.

The forward pass returns a view of the input and costs nothing; the backward pass costs one pass over the n x n gradient. The input is a matrix of shape (..., n, n); complex matrices use the transpose, not the conjugate transpose.
