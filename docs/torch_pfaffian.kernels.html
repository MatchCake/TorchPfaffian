torch_pfaffian.kernels.checked_linalg module¶

class torch_pfaffian.kernels.checked_linalg.CheckedLinalg¶

Bases: object

The LU-based torch.linalg functions TorchPfaffian uses, raising instead of returning corrupted results.

PyTorch factors a batch of matrices on CPU by splitting the batch over its threads, each calling MKL’s getrf, which above a size threshold starts its own team of threads. After torch.set_num_threads(n) with n >= 2, MKL runs n threads inside each of PyTorch’s, and the nested teams corrupt the factorizations of the matrices that need row swaps: from about m = 150, every such matrix of a batch of two or more comes out wrong (pytorch/pytorch#142815, #141358). inv and solve then sometimes raise on invalid pivots, but mostly the pivots look valid and the results are wrong without an error. A single matrix, a single thread and a thread count set at launch (OMP_NUM_THREADS) are not affected, nor is lu_solve given correct factors.

Each function here first checks the batched factorization, for the inputs that can be affected: a CPU batch of at least two matrices of size at least MIN_SIZE, with more than one thread. The check factors a probe, a batch of two Gaussian matrices of the input’s dtype and of size min(m, PROBE_MAX_SIZE), the same way, and verifies the factorization P L U of the second on a vector v against the componentwise backward-error bound of LU with partial pivoting, |A v - P L U v| <= c m eps (|P| |L| |U| + |A|) |v|. A failure raises a RuntimeError that explains the cause and the workaround. The verdict is cached per probe size, dtype and thread count, so the probe runs once for each and later calls cost a dictionary lookup; a call to torch.set_num_threads with another count runs it again, but one with the current count, which also corrupts the factorizations, is not seen after the first verdict. Other inputs go straight to PyTorch.

This is a workaround to remove once PyTorch fixes the issues (https://github.com/MatchCake/TorchPfaffian/issues/48).

torch_pfaffian.kernels.det_magnitude module¶

class torch_pfaffian.kernels.det_magnitude.LogMagnitudePfaffian(*args, **kwargs)¶

Bases: Function

Differentiable log|Pf(A)| = 0.5 * log|det(A)| using a single factorization in each direction.

The forward computes one torch.linalg.slogdet(); the backward supplies the analytic gradient 0.5 * (A^{-1})^T (Wirtinger-conjugated for complex inputs) through a single non-raising torch.linalg.inv_ex(), instead of differentiating through slogdet. Differentiating through slogdet forms grad * A^{-T}, which is infinite at an exactly-singular input, so even the correct upstream multiplier of 0 would give 0 * inf = NaN. Here exactly-singular elements (det(A) == 0, so slogdet returns sign 0) keep the correct -inf value and receive a zero gradient: the identity is substituted before the inverse so the factorization stays finite, and the gradient is masked to zero there. Numerically singular elements (a round-off det with nonzero sign) are already finite and left unchanged. No host synchronization happens in either direction.

torch_pfaffian.kernels.det_magnitude.log_magnitude_pfaffian(matrix: Tensor) → Tensor¶

Log-magnitude log|Pf(A)| = 0.5 * log|det(A)| of a batch of skew-symmetric matrices.

The value is computed through torch.linalg.slogdet(), so it works in the log domain and stays finite (and keeps its gradient alive) even for tiny Pfaffians such as probabilities of order 2^{-k} that would underflow the linear-domain sqrt(|det|). The gradient uses the analytic LogMagnitudePfaffian, a single factorization each direction that is NaN-free at exactly-singular inputs (see that class). Odd-dimensional inputs are singular, so the log-magnitude is -inf (returned with an autograd connection so a backward through it yields a zero gradient rather than raising, and without reading the entries so inf / nan inputs stay -inf).

Parameters:

matrix – Skew-symmetric matrices of shape (..., m, m), real or complex floating point.

Returns:

The log-magnitude of shape (...,) in the input’s real floating dtype (real for complex inputs, since a magnitude is real-valued).

torch.Tensor

Magnitude |Pf(A)| of a batch of skew-symmetric matrices, real-valued and differentiable.

The magnitude is obtained by exponentiating log_magnitude_pfaffian(). When epsilon is positive the log-magnitude is floored at 0.5 * log(epsilon) before exponentiation, reproducing the historical sqrt(clamp(|det|, epsilon)) floor as a function argument rather than a mutable global. Prefer the default 0.0 together with log_magnitude_pfaffian() for gradient-safe small probabilities.

torch_pfaffian.kernels.parlett_reid_slog module¶

torch_pfaffian.kernels.parlett_reid_slog.parlett_reid_slog(matrix: Tensor) → tuple[torch.Tensor, torch.Tensor]¶

Log-domain signed Pfaffian of a batch of skew-symmetric matrices via Parlett-Reid elimination.

The batched skew-tridiagonalization with partial pivoting is run device-side with no host synchronization (no .item(), .any() or isfinite().all()), and the result is accumulated as (phase, log|Pf|) rather than a raw product. The log domain removes both the overflow at large dimensions and the underflow for tiny Pfaffians (probabilities of order 2^{-k}). Real and complex inputs share the single code path: phase is +-1 (or 0) for real inputs and a unit-modulus complex number for complex inputs. An exact zero pivot column terminates that batch element cleanly with (0, -inf), since its remaining rank-2 updates vanish, so no epsilon threshold is needed.

Parameters:

matrix – Skew-symmetric matrices of shape (..., m, m), real or complex floating point.

Returns:

A pair (phase, log_abs) where phase has shape (...,) and matches the input dtype (with Pf = phase * exp(log_abs), and phase = 0 when Pf = 0), and log_abs has shape (...,) in the matching real dtype (-inf when Pf = 0). Odd m gives (0, -inf) and m = 0 gives (1, 0).

Return type:

tuple[torch.Tensor, torch.Tensor]

torch_pfaffian.kernels.parlett_reid_triton module¶

class torch_pfaffian.kernels.parlett_reid_triton.ParlettReidTriton¶

Bases: object

Parlett-Reid elimination of a batch of real skew-symmetric matrices in one Triton kernel launch.

PfaffianParlettReid on CUDA launches about a dozen small kernels per elimination step, so its run time is set by the m / 2 steps’ launches rather than by the arithmetic. Here one Triton program eliminates one matrix, and the batch is the grid, so the whole batch is one launch.

The elimination is blocked: the rank-2 updates of a panel of PANEL steps are delayed and applied to the trailing block in one pass at the end of the panel, which divides the traffic of the trailing block through memory by the panel size. Within a panel, each step forms the two columns it needs (the pivot column and the next) from the matrix as it was at the start of the panel, read as rows (the matrix is skew-symmetric), and the panel’s delayed updates; it swaps the pivot’s row and column into place, in the matrix and in the delayed update vectors, and stores its factor and pivot. The pivoting (the largest entry below the diagonal, the first on ties) matches the PyTorch loop, whose post-processing (sign, product, zero-pivot test) is shared; the results agree with it to round-off.

Triton has no complex arithmetic, so only float32 and float64 are supported, on CUDA, up to MAX_DIMENSION; supports() tells whether an input qualifies, and Triton is imported only then.

torch_pfaffian.kernels.small_n module¶

torch_pfaffian.kernels.small_n.small_pfaffian(matrix: Tensor) → Tensor¶

Signed/complex Pfaffian of a batch (..., m, m) for even m <= SMALL_N_MAX via unrolled matchings.

This is the compile-time form of the recursive expansion: the perfect matchings are enumerated once per dimension and evaluated as one batched gather followed by unrolled elementwise products and a matvec with the sign vector, with no elimination loop or data-dependent control flow. The factor product is unrolled (rather than torch.prod()) so that zero entries still get correct product-rule gradients, making the kernel exact and autograd-friendly for the supported sizes.

Parameters:

matrix – Skew-symmetric matrices of shape (..., m, m) with even m <= SMALL_N_MAX.

Returns:

The signed Pfaffian of shape (...,), sharing the input backend, dtype and device.

Return type:

torch.Tensor
