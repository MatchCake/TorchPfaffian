TorchPfaffian: PyTorch-Based Pfaffian Computation¶

Description¶

TorchPfaffian computes the Pfaffian of batches of skew-symmetric matrices in PyTorch, with exact gradients on CPU and GPU, in float32, float64, complex64 and complex128 (float16, bfloat16 and complex32 inputs are computed in float32 or complex64).

Statement of need¶

Pfaffians appear wherever fermions are paired: the overlaps and amplitudes of fermionic Gaussian states, the simulation of matchgate (free-fermion) quantum circuits, BCS and Hartree–Fock–Bogoliubov wave functions, the partition functions of planar Ising models and perfect-matching counts. In these settings the Pfaffian is usually one step of a larger differentiable model that runs on batches of matrices, often on a GPU, and is optimized by gradient descent.

The reference implementation, pfapack, works on single NumPy arrays, without automatic differentiation or GPU support. The determinant torch.linalg.det gives only Pf(A)^2 = det(A) and loses the sign, which carries the physics (interference between amplitudes). torchpfaff brings a differentiable Parlett–Reid Pfaffian to PyTorch, with a Triton kernel on CUDA, for real matrices. TorchPfaffian fills the remaining gap: a signed, batched and differentiable Pfaffian that is a drop-in PyTorch operation, for real and complex matrices, with exact gradients at singular matrices. It is the Pfaffian backend of the MatchCake matchgate simulator.

Features¶

  • One entry point, automatic routing. pfaffian() picks the fastest correct strategy for the input (size, dtype, device, block structure, whether gradients and the sign are needed) from a registry of strategies: an exact unrolled kernel for small matrices, Parlett–Reid tridiagonalization in Rust (CPU) and in PyTorch (any device), determinant-based magnitudes, and a block-determinant path for matrices of the form [[0, B], [-B^T, 0]].

  • Exact gradients, including at singular matrices. The backward of Pf(A) is Pf(A) A^{-T} / 2 when A is invertible. At singular A, where the inverse does not exist but the gradient does, it is computed exactly from the Pfaffian adjugate. Complex inputs follow PyTorch’s Wirtinger convention.

  • Overflow-safe. Results that overflow the dtype in the linear domain are recomputed in the log domain; slog_pfaffian() returns (phase, log|Pf|) directly.

  • Round-off zeros. mask_roundoff_gradient=True gives a zero gradient to Pfaffians that vanish up to round-off, such as parity-forbidden amplitudes.

  • Batched and device-agnostic. Any leading batch shape, on CPU or CUDA. On CPU, a native Rust kernel computes the Pfaffian and the inverse of its backward. On CUDA, small inputs are computed by that kernel on the host (the device would be bound by kernel launches), and larger real ones by a single Triton kernel per batch. On CPU it is faster than pfapack’s C implementation on batches of small matrices, and on batches of large ones with several threads; on a single matrix, pfapack is faster. See the performance page.

  • Low-rank updates. LowRankPfaffian gives Pfaffian ratios and updated inverses under low-rank updates and row replacements, PfaffianUpdater chains them (with delayed updates), and PfaffianChain grows a matrix block by block for qubit-by-qubit sampling. On CPU without gradients they run in Rust kernels.

Requirements¶

  • Python 3.10 to 3.14 and PyTorch 2.1 or newer.

  • Prebuilt wheels with the Rust kernel are published for Linux x86_64, Windows x86_64 and macOS arm64. On other platforms pip builds the package from source, which needs a Rust toolchain (https://rustup.rs).

Installation¶

pip install torchpfaffian

On Linux, pip installs the CUDA build of PyTorch by default. For a CPU-only environment, install PyTorch first from its CPU index:

pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install torchpfaffian

For development, this project uses uv. From a clone of the repository:

uv sync --dev --extra cpu
uv run maturin develop --release -m rust/Cargo.toml

The cpu, cu128 and cu130 extras select the PyTorch build; they only take effect with uv from a clone. --release matters: maturin develop builds the Rust kernel in debug mode by default, which makes it much slower. See CONTRIBUTING.md for the full development workflow.

Usage¶

import torch

from torch_pfaffian import pfaffian, slog_pfaffian

# Any skew-symmetric matrix of shape (..., 2n, 2n).
matrix = torch.tensor([[0.0, -3.0], [3.0, 0.0]])

pf = pfaffian(matrix)                 # signed Pfaffian (default)
magnitude = pfaffian(matrix, sign=False)  # |pf|, through the faster determinant-based path

pfaffian() chooses the strategy from the input; the full routing table is in its documentation. To force a strategy, use get_pfaffian_function(name), for example get_pfaffian_function("PfaffianParlettReid")(matrix).

Gradients flow through every path:

matrix = torch.randn(32, 10, 10, dtype=torch.float64)
matrix = (matrix - matrix.transpose(-1, -2)).requires_grad_()

pfaffian(matrix).sum().backward()     # matrix.grad = Pf(A) A^{-T} / 2 per batch element
phase, log_abs = slog_pfaffian(matrix.detach())  # log domain, never overflows

Pfaffian ratios under low-rank updates¶

Monte Carlo moves and neural quantum states often only need Pf(A') / Pf(A) for a matrix A' that differs from A by a few rows and columns. Given A^{-1}, LowRankPfaffian computes that ratio in O(n^2 k) (O(n) for one replaced row) instead of the O(n^3) of a new Pfaffian, together with the updated inverse. It follows the convention of lrux: A' = A - u J u^T with u of shape (n, 2k) and J = [[0, I_k], [-I_k, 0]].

from torch_pfaffian import PfaffianUpdater, pfaffian_ratio, pfaffian_ratio_replace_and_inverse

inverse = torch.linalg.inv(matrix.detach())                 # (32, 10, 10)
update = torch.randn(32, 10, 2, dtype=torch.float64)       # rank-2 update u = (x, y)
ratio = pfaffian_ratio(inverse, update)                     # Pf(A - u J u^T) / Pf(A)
change = torch.randn(32, 10, dtype=torch.float64)
ratio, new_inverse = pfaffian_ratio_replace_and_inverse(inverse, 3, change)  # row and column 3 change

updater = PfaffianUpdater(matrix.detach(), max_delay=4)    # delayed inverse updates for long chains
accepted = torch.rand(32) < updater.ratio(update).abs() ** 2
updater.accept(update, mask=accepted)                       # only the accepted walkers move

For a matrix that grows block by block, as in qubit-by-qubit sampling of matchgate circuits, pfaffian_extension_ratio gives Pf([[A, B], [-B^T, C]]) / Pf(A) = Pf(C + B^T A^{-1} B) from A^{-1}, and PfaffianChain keeps the inverse from one qubit to the next, so that a sample of n qubits costs O(n^3) instead of O(n^4):

from torch_pfaffian import PfaffianChain

chain = PfaffianChain((shots,))                              # starts from the empty matrix
for qubit in range(n_qubits):
    modes = slice(2 * qubit, 2 * qubit + 2)
    border = covariance[..., : 2 * qubit, modes]             # (shots, 2 qubit, 2)
    corners = covariance[..., modes, modes] + outcome_blocks # (shots, 2, 2, 2): the blocks for y = 0 and 1
    probabilities = chain.ratios(border, corners).abs() / 2  # conditional probabilities, (shots, 2)
    outcome = torch.multinomial(probabilities, 1)[..., 0]
    chain.extend(border, corners[torch.arange(shots), outcome])

For long runs on small matrices, where PyTorch’s per-operator overhead dominates, CompiledLowRankPfaffian (and PfaffianChain(..., compiled=True), PfaffianUpdater(..., compiled=True)) runs the same computations through torch.compile: a few seconds of compilation on first use, then about 2x faster inverse updates on a single matrix, on CPU and CUDA. The eager LowRankPfaffian stays the default.

Everything is batched, differentiable, and runs on CPU and CUDA. Gradients are exact for any skew-symmetric construction of the inputs, such as a covariance matrix computed from circuit parameters; the gradient with respect to a raw inverse leaf follows the skew-split convention of pfaffian(), while those with respect to blocks sliced from a leaf matrix (border, corner) are only meaningful in their skew-symmetric part. Functions that also return the updated inverse have their own name (..._and_inverse) rather than a flag. pfaffian_ratio, pfaffian_ratio_and_inverse, pfaffian_ratio_replace, pfaffian_ratio_replace_and_inverse, pfaffian_extension_ratio, pfaffian_extension_ratio_and_inverse and skew_identity are shortcuts to the static methods of LowRankPfaffian.
